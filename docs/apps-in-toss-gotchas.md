# 앱인토스 미니앱 — 다음번엔 여기서 막히지 않기 위해

새 앱을 시작할 때 이 파일부터 읽는다. 이번 프로젝트에서 **실제로 시간을 잡아먹은
것들만** 적었다. 공식 문서에 있는 내용은 빼고, 문서에 없거나 문서와 달랐던 것만 남긴다.

한 줄 요약: **반나절을 흰 화면에 썼는데, 원인은 파일 하나가 없어서였다.**
그리고 그 사실을 알아내는 데 오래 걸린 이유는 **오류를 볼 수 있는 자리에 서지 않고
번들부터 뒤졌기** 때문이다.

---

## 0. 막혔을 때의 순서 — 이것만 지켜도 대부분 아낀다

```
1. 샌드박스 앱으로 붙어서 오류를 본다        ← 여기부터. 예외 없이.
2. 오류 문구를 그대로 읽고 고친다
3. 그래도 모르면 그때 번들·설정·버전을 본다
```

이번에 1번을 건너뛰고 3번부터 시작했다. `target`·React 버전·번들 구조를 반나절
뒤졌고 **전부 헛다리였다.** 샌드박스로 붙은 지 10분 만에 진짜 오류가 나왔다.

흰 화면에는 정보가 없다. 정보가 없는 화면을 오래 들여다보는 대신, 정보가 나오는
자리로 먼저 옮겨간다.

---

## 1. 흰 화면 + "잠시 문제가 생겼어요"

이 문구는 **우리 번들에 없다.** 토스가 네이티브에서 그린다. 그래서 이게 보인다는 건
"JS가 화면을 못 그렸다"는 뜻 이상은 아니다. 원인은 아래 셋 중 하나였다.

### (a) `pages/_404.tsx`가 없다 ← 이번의 진짜 원인

granite 라우터는 화면 목록에서 `/_404`를 못 찾으면 **첫 렌더에서 그냥 던진다.**
조건이 없다. 파일 하나가 없으면 앱이 매번 예외 없이 죽는다.

```tsx
// @granite-js/react-native — router/utils/screen.tsx
const notFoundPage = routeScreens.find((s) => s.path === '/_404');
if (notFoundPage == null) {
  throw new Error('404 page not found. Please create a `_404.ts` or `_404.tsx` ...');
}
```

**진입 파일에 ErrorBoundary를 달아도 안 잡힌다.** AppRoot가 Router에 우리 앱을
`container` prop으로 넘기기 때문에, 우리 ErrorBoundary는 Router보다 **아래**다.

```tsx
// AppRoot.tsx
<Router context={context} container={Container} ... />
```

Router가 자기 렌더 중에 던지면 우리 컨테이너는 마운트조차 안 된다 → 오류 화면도
안 뜬다 → 흰 화면.

> **새 앱 체크리스트:** 화면을 하나도 안 만들어도 `pages/_404.tsx`는 만든다.
> `createRoute('/_404', { component })` 한 줄이면 된다.

### (b) `react-native` 버전이 런타임과 다르다

샌드박스에서 이렇게 나온다:

```
Requiring module ".../Platform.ios.js", which threw an exception:
Invariant Violation: TurboModuleRegistry.getEnforcing(...):
'PlatformConstants' could not be found.
```

DevTools 제목줄의 `React Native: 0.84.0`이 네이티브 버전이다. 여기에 우리가
`react-native@0.72.6`의 JS를 보내고 있었다.

`package.json`을 CLI가 정한 값에 맞춘다:

| 패키지 | 값 |
|---|---|
| `react-native` | `0.84.0` |
| `react` | `19.2.3` |
| `@types/react` | `19.2.3` |

이 표는 `@apps-in-toss/react-native-cli`의 마이그레이션 프리셋에 그대로 있다.
다만 **`@granite-js/*`는 그 표의 `1.0.18`로 내리지 말 것.** 1.0.18에는
`useKeyboardHeight`가 없어서 쓰고 있으면 컴파일이 깨진다. 표는 최소선이지 상한이 아니다.

> **개발과 배포에서 react-native가 오는 곳이 다르다.** 이걸 모르면 엉뚱한 데를 판다.
>
> | | react-native JS | 확인법 |
> |---|---|---|
> | `granite dev` (샌드박스) | **번들에 들어간다** | 개발 번들에 `getEnforcing('PlatformConstants')`가 있다 |
> | `ait build` (배포) | 호스트가 준다 | 배포 번들엔 `__SHARED__["react-native"]`만 있다 |
>
> 그래서 이 고침은 샌드박스만 고쳤고 배포본 흰 화면은 (a)가 원인이었다.
> 배포 번들이 **바이트 크기까지 같은지** 비교해 보면 이런 착각을 빨리 깰 수 있다.

### (c) 토스 앱 버전이 낮다

프레임워크가 기준 미만이면 우리 앱을 아예 안 그린다.
**최소: Android 5.220.0 / iOS 5.221.0.** 샌드박스는 이 게이트를 건너뛴다.

## 2. `granite.config.ts`의 `target` — 적지 말 것

`ait build`는 런타임 두 벌(0.84.0 · 0.72.6)을 만드는데, **0.72.6 쪽만** CLI가 임시
설정에 target을 주입하고 0.84.0 쪽은 이 파일을 그대로 쓴다.

그래서 여기에 `'0.72.6'`을 적으면 0.84 번들까지 0.72 호환 변환을 받아 **두 번들이
바이트까지 같아진다.** 런타임을 나눠 만드는 의미가 사라진다. 비워 두면 기본값 0.84.0.

(이게 흰 화면의 원인이라고 한참 믿었지만 아니었다. 실제 원인은 위의 (a)다.)

## 3. 새 프로젝트에 빠지기 쉬운 파일들

`create-granite-app` 템플릿과 비교해 보면 금방 나온다. 없어서 막혔던 것들:

| 파일 | 없으면 |
|---|---|
| `index.ts` (루트) | dev 서버가 `Error: Can't resolve './index'`로 멈춤 |
| `src/pages/_404.tsx` | **흰 화면** (위 1-a) |
| `babel.config.js` | `module.exports = { presets: ['babel-preset-granite'] };` |
| `react-native.config.js` | `reactNativePath`를 명시 |

루트 `index.ts`는 이렇게 생겼다:

```ts
import { register } from '@granite-js/react-native';
import App from './src/_app';

register(App);
```

## 4. CLI — 공식 문서의 명령 표가 실제와 다르다

실제로 쳐 보고 확인한 값이다.

| 문서에 적힌 것 | 실제 |
|---|---|
| `ait token add [워크스페이스] [API키]` | `npx ait token add [--api-key <키>] [프로필]` |
| `ait deploy [워크스페이스] [API키]` | `npx ait deploy [--api-key <키>] [--profile <프로필>]` |

그리고:

- **`ait`는 전역이 아니다.** 반드시 `npx ait`. 아니면 `zsh: command not found: ait`.
- **키 고르는 순서가 `저장된 프로필 → --api-key`다.** 프로필에 옛 키가 남아 있으면
  `--api-key`로 새 키를 줘도 **조용히 무시된다.** 키를 바꿀 땐 `npx ait token remove` 먼저.
- 토큰은 `~/.ait/credentials`에 저장된다. **터미널을 닫아도 안 날아간다.**
- `npm run build`가 `.ait`를 안 만들면 스크립트가 `granite build`로 되어 있는 것이다.
  `.ait`를 만드는 건 **`ait build`**다.

### macOS 터미널에서 붙여넣기

zsh는 `interactive_comments`가 꺼져 있어서 **`#` 주석이 인자로 들어간다.**

```
npx ait token add  # 설명       ← '#'과 '설명'이 인자가 되어 실패
```

복사용 명령 블록에는 주석을 절대 넣지 않는다. 설명은 블록 밖에.

## 5. 샌드박스 앱 붙이기

앱스토어 → **"앱인토스 샌드박스"** (id6745618667, iOS 16+).

1. 맥과 폰을 **같은 Wi-Fi**에 둔다.
2. 맥에서 `npm run dev` → `ifconfig | grep "inet "`로 맥 IP 확인.
3. 샌드박스 앱에서 **'로컬 네트워크' 권한 허용** → 서버 주소에 그 IP 입력.
4. `intoss://{appName}`으로 연다.

이번에 여기서 헤맨 것들:

- 핫스팟으로는 안 됐다. `ifconfig -a`에 `en0`가 `NOARP`/`constrained`로 뜨고
  "not associated with an AirPort network"이면 Wi-Fi가 아예 안 붙은 것이다.
  같은 공유기 Wi-Fi로 바꾸니 바로 됐다.
- 사파리로 `http://<맥IP>:8081/status`를 열면 **파일 다운로드로 뜬다.** 정상이다.
  받아진 파일에 `packager-status:running`이 들어 있으면 서버가 살아 있는 것.
- `EADDRINUSE`는 dev 서버가 이미 떠 있다는 뜻. 새 창을 열지 말고 원래 창에서 `Ctrl+C`.
- DevTools는 dev 서버 창에서 **`j`**. 여기 콘솔이 진짜 오류가 나오는 자리다.

**개발 중 디버깅은 무조건 샌드박스다.** 배포해서 여는 건 최종 확인용이다.

## 6. 배포와 키

- 비밀값은 **커밋되지 않는 파일**에만 둔다: `src/config.local.ts`, `proxy/.env`.
  둘 다 `.gitignore`에 있고, 터미널을 닫아도 남는다.
- **채팅창에 키를 붙여넣지 않는다.** 대화 기록에 그대로 남는다.
  (이번에 공공데이터포털 인증키가 스크린샷으로 노출돼서 재발급해야 했다.)
- 키 입력은 가려진 입력으로 받는 스크립트를 쓴다. 화면에도 명령 기록에도 안 남게.
- 배포는 **키가 있는 기계에서** 한다. 원격 세션에서 하면 `config.local.ts`가 빈
  껍데기라 **가짜(mock) 경로를 쓰는 앱이 올라간다.**
- `npm run check-config`처럼 **값이 아니라 글자 수만** 찍는 점검 스크립트를 하나 둔다.
  캡처해서 공유해도 안전하다.

## 7. 스토어 등록에서 걸렸던 것

- 스크린샷 규격이 **정확해야** 한다. 세로 636×1048 최소 3장, 가로 1504×741 최소 1장.
  규격 밖은 그냥 안 세어진다.
- 아이콘은 **파일 경로가 아니라 이미지 주소(URL)**다. 프레임워크가 그 값을 그대로
  `<Image source={{ uri }} />`에 넘긴다. `'./assets/icon.png'`는 영영 안 뜬다.
- 약관 **체크박스 두 개**를 모두 눌러야 한다. 하단 것을 빠뜨리기 쉽다.
- 검토 요청 후에도 앱은 계속 수정·재배포할 수 있다.

### 스토어 그림은 앱 코드에서 만든다

손으로 그린 스크린샷은 **반드시 어긋난다.** 이번에도 "6:30 약속"이라고 적어 뒀는데
실제 앱은 `formatClock`으로 "오후 6시 30분"을 그리고 있었고, "12.4km"라고 적은 곳의
실제 값은 "12.43"이었다.

스크린샷 생성 스크립트가 앱의 **토큰·문구·포맷 함수를 그대로 import**하게 만든다.
숫자도 손으로 적지 말고 상수에서 뽑는다 — 안 그러면 상수를 바꾸는 날 그림만 옛말을 한다.

## 8. 지도 — 키 없는 선택지의 실제

앱인토스 런타임에는 **지도 네이티브 모듈이 없다.** 그래서 지도 SDK를 붙이는 대신
**래스터 타일을 `<Image>`로 직접 깔고 그 위에 SVG로 경로를 그렸다.** 웹 메르카토르
계산만 있으면 되고(`src/ui/mercator.ts` 60줄) 의존성이 하나도 안 늘어난다.

키 없는 타일을 찾아본 결과는 이렇다.

| 제공자 | 키 없이 되나 | 출시 앱에 써도 되나 |
|---|---|---|
| **CARTO** (Positron) | **지금은 된다**(실측 200 OK) | 문서상 무료 키를 요구한다. 월 500만 타일까지 무료, **상업적 사용은 별도 라이선스** |
| OpenStreetMap 기본 | 된다 | 되지만 규칙이 빡빡하고(고유 User-Agent 필수, **오프라인/미리받기 전면 금지**) 색이 화려해서 톤이 안 맞는다 |
| OpenFreeMap · VersaTiles | 된다, 조건도 깨끗하다 | **벡터 전용.** MapLibre가 필요해서 WebView를 띄워야 한다 |
| Stadia(Stamen) · Esri · Wikimedia | 아니다 | 키 필요하거나 제3자 사용 금지 |

**결론: 조건까지 깨끗한 키 없는 래스터 타일은 없다.** CARTO는 보기에 가장 맞고 지금
동작하지만, 그건 문서화된 보장이 아니다. 그래서 **타일 주소를 `config.ts`로 뺐다** —
키를 붙이거나 제공자를 갈아탈 때 화면 코드를 안 고치려는 것이다. 무료 타일 서비스는
전부 SLA가 없고, 막히는 날이 앱을 다시 배포해야 하는 날이 되면 곤란하다.

출처 표기는 **지우면 안 된다.** OSM은 ODbL이, CARTO는 이용 조건이 요구한다.
아주 작게 두더라도 읽히긴 해야 한다 — 무늬 많은 타일 위에서는 흰 바탕을 깔아 준다.

타일을 직접 깔 때 걸리는 두 가지:

- **배율은 소수로 낸다.** 정수 단계로만 고르면 한 단계 차이가 두 배라, 한 뼘 넘칠
  때마다 경로가 절반으로 작아진다(화면 폭의 20%만 쓰는 그림이 나왔다).
  소수로 내고 타일 크기로 그 나머지를 메운다.
- **어느 정수 배율의 타일을 받을지는 기기 화소로 정한다.** 한쪽으로만 반올림하면
  둘 중 하나를 잃는다 — 내리면 타일이 늘어나 흐려지고, 올리면 타일에 구워진 글자가
  절반 크기가 되어 안 읽힌다. 타일 하나가 실제 화소로 원본 크기에 가장 가깝게
  놓이는 배율을 고르면 둘 다 피한다.

## 9. 코드 쪽에서 되풀이하지 말 것

앱인토스와 직접 상관은 없지만 이번에 값을 치른 것들.

- **`ait migrate`는 granite를 1.0.42 → 1.0.18로 내린다.** 버전 표에서 React/RN만
  가져오고 granite는 그대로 둔다.
- **사용자에게 보이는 숫자는 상수 하나에서 뽑는다.** "3분"을 5분으로 바꿀 때
  손으로 적어 둔 자리가 여덟 군데 있었고 그중 둘이 화면에 보이는 문장이었다.
- **점수와 문턱을 헷갈리지 않는다.** 점수는 후보 사이의 **순서**만 정한다.
  전부 나쁘면 그중 제일 나은 게 1등이 된다. "이건 절대 안 된다"는 순위가 아니라
  문턱으로 막아야 한다.
- **비율을 넘길 땐 어느 자로 잰 것인지 같이 정한다.** 미터로 잰 비율을 그림 좌표
  길이에 쓰면 조용히 어긋난다(서울에서 경도는 0.8배로 눌린다).
- **재보지 않은 값으로 이유를 말하지 않는다.** 환경 데이터를 안 부르고 만든 경로는
  novelty가 늘 1.0으로 나와서, 매일 걷는 길에 "아직 안 가보신 길이에요"라고 하게 된다.
