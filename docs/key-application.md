# API 키 신청 기입값

각 포털의 신청 폼에 그대로 넣을 값. 심사자가 읽고 판단하는 칸이므로
"무엇을, 왜, 어떻게 쓰는지"가 한 번에 보이게 쓴다.

---

## 1. 서울 열린데이터광장 (혼잡도 · `quiet`)

[data.seoul.go.kr](https://data.seoul.go.kr) → 로그인 → Open API → 인증키 신청

| 항목 | 기입값 |
|---|---|
| **서비스(사용) 환경** | `앱개발 (모바일 솔루션 등)` |
| **사용URL** | `https://github.com/won-topiaa/some-time-left` |
| **관리용 대표 이메일** | 본인 이메일 |
| **활용용도** | `도보 경로 추천 서비스의 지역 혼잡도 반영` |
| **내용** | 아래 문단 |

```
약속 시각 5분 전에 도착하도록 도보 경로를 추천하는 앱입니다. 최단 경로 대신
남은 시간에 맞는 우회 경로를 제안하며, 실시간 인구데이터의 지역 혼잡도를
반영해 한적한 길을 우선 추천합니다. 자체 서버에서 5분 주기로 캐싱해
호출하며, 데이터는 재배포 없이 경로 추천 지표로만 사용합니다.
```

**체크박스 두 개를 모두 눌러야 한다.** 상단 `위 약관에 동의합니다`와
하단 `(필수) 위 개인정보 수집 이용에 동의합니다`. 하단을 빠뜨리기 쉽다.

### 왜 이렇게 고르나

- **환경을 `앱개발`로**: 최종 소비자가 토스 안의 미니앱이다. 호출 자체는
  서버(프록시)가 하지만, 심사 관점에서 중요한 건 결과물의 형태다.
- **사용URL에 리포지토리 주소**: 프록시를 아직 배포하지 않았다. 서울은 이 값으로
  호출을 제한하지 않고 기록용으로 받는다(브이월드의 도메인 등록과 다르다).
  프록시를 먼저 배포했다면 그 주소를 넣는 편이 더 정확하다.
- **내용에 "캐싱"과 "재배포 없음"을 명시**: 열린데이터 심사에서 자주 보는 두 가지
  우려가 과도한 호출과 데이터 재판매다. 둘 다 아니라는 걸 먼저 밝힌다.

### 발급 후

인증키는 **앱이 아니라 프록시**에 넣는다. 서울 API는 평문 HTTP 전용이라
앱에서 직접 부를 수 없다([`proxy/README.md`](../proxy/README.md)).

리포지토리를 로컬에 받은 뒤(`git clone` → `cd some-time-left`), **한 줄씩** 실행한다.

```bash
cd proxy
npm run setup    # 인증키를 물어보고 .env를 만든다 (토큰은 자동 생성)
npm run check    # 서버 없이 인증키가 살아 있는지 확인
npm run dev      # 확인됐으면 프록시 실행
```

Node 22.9 이상이 필요하다. 낮으면 스크립트가 먼저 알려준다.

`npm run check`가 이렇게 나오면 성공이다.

```
  ✓ 광화문·덕수궁      보통 (2026-08-18 03:20)
  ✓ 강남역            붐빔 (2026-08-18 03:20)
```

인증키는 어느 출력에도 찍히지 않는다.

## 2. 공공데이터포털 (공원 · `scenic`)

[data.go.kr](https://www.data.go.kr) → 로그인 → API 검색 → 활용신청

**두 개를 각각 신청한다.** 인증키는 하나지만 활용신청은 API마다 따로다.

- 전국도시공원표준데이터
- 국토교통부_건축물대장정보 서비스

| 항목 | 기입값 |
|---|---|
| 활용목적 | `앱 개발` |
| 상세 기능 | `도보 경로 주변의 공원·수변 근접도를 계산해 경로 추천에 반영` |

> **Decoding 키를 쓴다.** Encoding/Decoding 두 가지가 발급되는데 코드가
> `URLSearchParams`로 인코딩하므로 Decoding 키를 넣어야 한다. 헷갈리면
> `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 뜬다.

## 3. 브이월드 (건물 높이 · `shade`)

[vworld.kr](https://www.vworld.kr) → 오픈API → 인증키 발급

| 항목 | 기입값 |
|---|---|
| 활용 용도 | `보행 경로의 그늘 비율 계산 (건물 높이 × 태양 위치)` |
| **사용 도메인** | 프록시를 배포한 도메인 |

> 브이월드는 **도메인 등록이 실제 제약**이다. 등록하지 않은 도메인에서 호출하면
> 거부된다. 서울·공공데이터포털과 다른 점이니 주의.

발급 후 레이어 아이디를 확정한다:

```bash
node scripts/discover-vworld.mjs <VWORLD_KEY>
```

## 4. TMAP (경로·검색·혼잡도)

[openapi.sk.com](https://openapi.sk.com) → 대시보드 → 앱

앱 키는 **앱 단위**로 발급되지만 **상품마다 사용 신청을 따로** 해야 한다.
신청할 때 그 상품을 포함할 앱을 고른다.

| 상품 | 쓰는 곳 |
|---|---|
| 경로안내 (보행자) | 도보 경로 |
| 장소검색 | 목적지 이름 검색 |
| 지오코딩 | 주소 → 좌표 |
| puzzle 장소 혼잡도 | 목적지 혼잡도 |

신청이 됐는지는 이걸로 확인된다:

```bash
npm run probe-tmap
```

## 우선순위

키가 다 필요하지는 않다. **TMAP만 있으면 앱이 돈다.**

| 순위 | 키 | 없으면 |
|---|---|---|
| 필수 | TMAP appKey | 경로 자체가 mock |
| 높음 | 서울 (프록시에) | `quiet` 중립값 |
| 중간 | 공공데이터포털 | `scenic` 중립값 |
| 낮음 | 브이월드 | `shade` 기본 높이 15m |
